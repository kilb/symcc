Production mechanism:
- rank 0 strictly broadcasts result/input budgets before shared-state creation
- default input limit is 268435456 bytes; valid range is 1..1099511627776
- result total-byte limit must not exceed the per-input byte limit
- external scans and public scans use context-managed scandir
- imported-name state retains dev/inode/size/mtime/ctime identity, not only name
- stable hash snapshot uses O_NOFOLLOW, same-fd fstat, fixed 1 MiB reads, and final path stat
- rendezvous owner reopens the exact snapshot identity for fsync-backed content publication
- source mutation/replacement leaves no cache/public/temp commitment and is retryable
- deterministic input overflow publishes and dispatches nothing, then takes Abort(70)
- worker public-to-private copy computes expected SHA-256 in the copy pass
- final accounting consumes canonical 64-hex no-follow regular entries only
- final new-interesting count subtracts the complete shutdown-time external hash set

Strict boundary:
- Path/hash/identity/provenance metadata remains O(number of observed corpus names).
- Every master still hashes each new external input before content-owner selection.
- The owner intentionally performs a second stable source pass for publication identity.
- A byte budget cannot preempt a synchronous filesystem call already in progress.
- Final-component O_NOFOLLOW does not provide a Byzantine parent-directory model.
- The benchmark uses local sparse/page-cached files and isolates mechanism cost.
- No real multi-host, NFS/Lustre/GPFS, storage failover, or power-loss evidence exists.
- No DSE throughput, solver, coverage, campaign, bug-discovery, or LAVA-M uplift is claimed.
